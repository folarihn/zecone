## Selected real route

The first bounded action is `SOLANA_DEVNET_SPL_SWAP`, using the existing trusted inventory settlement journal, ten-confirmation Zcash verifier and native builder. It is not a trustless bridge or native ZEC-to-SPL exchange.

Official Raydium sources distinguish devnet CPMM program `DRaycpLY18LhpbydsBWbVJtxpNv9oXPgjRSfpF2bWpYb`. Its maintained demo explicitly reads devnet pools from RPC because its pool API does not supply devnet data. We inspected actual pool accounts and liquidity through the genesis-checked devnet endpoint instead of assuming website or aggregator support. Jupiter's published swap API was reviewed, but no usable verified devnet route was established; no Jupiter request is part of this implementation. No custom AMM is needed for the verified Raydium route. No production DEX compatibility is claimed.

The one allowlisted pool is `12aukygfT6qr5KH9MeeVYb4Y9rsmTzAVzUn633BRCfd`. Input is WSOL, `So11111111111111111111111111111111111111112`, 9 decimals. Output is `2j76mnkJEBxbYv8T9c76PbsGzf5XuhpRoK1kwwTg9MpY`, 6 decimals. It is an arbitrary devnet test token: no symbol, price, redeemability or USDC identity is asserted. Both mint accounts are legacy SPL, exact 82-byte layout, initialized, with no mint/freeze authority. Token-2022/extensions, delegate/close-authority token accounts and creator-fee pools are rejected.

`cpmm.ts` checks exact pool/config/vault/observation ownership and discriminators, mint/program bindings, status/open time, decimals, balances and protocol/fund/creator-fee reserve deductions. It verifies the executable program's loader and program-data pointer plus the captured SHA-256 of the entire program-data account. The program is upgradeable; any drift requires manual review. A matching public address/hash is not a reproducible-build attestation or proof the operator cannot upgrade it.

Fixed input is **1,000,000 WSOL units / 0.001 WSOL**. Maximum slippage is **100 bps / 1%**. Fee ceiling is **10,000 lamports**; new ATA rent ceiling is **3,000,000 lamports each**, at most two accounts. The relayer wraps its own SOL. The selected recipient does not need a public funding transaction from a known user wallet. The immutable checkout quotes **0.001 TAZ** at explicitly simulated demonstration pricing; it is not a market exchange rate. Checkout validity is two hours; prepared swap approval expires within 90 seconds and is also limited by its blockhash. Price deterioration below the immutable minimum requires recovery, not silently relaxed slippage.

The exact five-instruction legacy transaction creates the relayer WSOL ATA idempotently, transfers the fixed SOL input, synchronizes native balance, creates the recipient output ATA idempotently, and performs Raydium `swap_base_input` directly into that ATA. The complete message is reconstructed and compared before signing. No API route bytes, arbitrary instructions, lookup tables, tips, approvals or token transfer fees are accepted. Source ATA must be empty before wrapping.

## Existing settlement integration

The shared adapter has an optional bounded swap policy; its default Phase 7B delivery path remains available and its existing regression tests pass. Phase 7C uses separate profile/watch/journal/browser files, a distinct order namespace and fresh Zcash receiving credentials. At the user's explicit request, the funded disposable Phase 7B payer and relayer supply inventory directly. Their key files and wallet databases stay untouched; a new source watch/construction database uses the selected payer's viewing authority and local seed over stdin. Historical payment authorization cannot enter the new order. Exact incoming amount, owned Ironwood notes, fresh complete scans and at least ten confirmations remain mandatory. Excess/expired payments and inconsistent chain evidence require recovery.

Signing claims and approved signed bytes are persisted before a sole submission attempt. Uncertain outcomes retain the original signature. Reconciliation requires a finalized receipt, exact approved message/signature/fee, exact input-vault increase, matching output-vault decrease and recipient-token increase above the minimum, recipient ownership, mint/program/decimals, empty residual WSOL balance and relayer debit including bounded rent. Simulation or token-account existence alone never completes an order. Completed orders veto execution and refund recovery. Interrupted signing/recovery rules are retained.

## Accounts and user interface

Expired **unsigned** swap reviews can be retired manually with `npm run phase7c -- retire-expired-unsigned --review-expired-unsigned`. This requires fresh confirmed payment evidence and either elapsed quote expiry or an invalid blockhash, and archives the old prepared bytes. Any signing claim, signature or signed wire vetoes replacement. Preparing again requires a new exact human approval; expired approval never carries forward. See [separate lifetimes, recovery rehearsal and local exact approval](PHASE7C-APPROVAL-RECOVERY.md). A 30-minute economic review does not authorize signing; the local exact transaction prompt fetches the blockhash only after readiness.

New Solana relayer/recipient keys use standard age-v1 file encryption via pinned `age-encryption` **0.3.1**. The library uses its standard scrypt password stanza and authenticated payload encryption. A random unlock secret is sealed with Windows DPAPI CurrentUser; neither plaintext seed nor passphrase is written by setup. An explicit local unlock is required for signing. Existing plaintext wallets are not migrated. The fresh encrypted recipient is active; the fresh encrypted relayer remains unfunded/unused because the user selected the previously funded relayer directly. That reused relayer's credential remains plaintext and is only loaded by the explicit operator signing command, not the Phase 7C browser backend. Same-user malware and an unlocked compromised process are not isolated. See [privacy audit and recovery procedure](PHASE7C-PRIVACY-AUDIT.md).

The new checkout defaults to a fresh encrypted local recipient and can select a registered previous local recipient with a reuse acknowledgment. Key generation/registration/backup are local CLI operations, outside the backend; the backend only reads public descriptors. The UI shows input/output mints, exact base-unit quantities, minimum received, slippage, fees/rent caps, quote expiry, privacy disclosure, confirmation progress, execution/recovery state and finalized result. Payment address reveal is explicit and temporary. Signing/broadcast/refunds are unavailable through browser APIs.

User history is an allowlisted projection with a random session-scoped handle. It omits operator IDs, payment transaction IDs, watch account hashes, viewing keys, raw notes, signed wire and the private cross-chain join. Another session cannot enumerate or reveal the order. URLs contain no order/payment identifiers; explorer links contain only the public Solana signature and `cluster=devnet`. Necessary full payment/authorization/audit/recovery records stay in gitignored operator storage. This is data minimization, not unlinkability from the operator.

## Commands and approvals

`npm run phase7c:profile` reserves a new identity and refuses overwrite. Do not run it again for the existing profile. `npm run phase7c:wallet` starts the separately paired local checkout. Existing EVM/Phase 7A/7B entry points remain available; the isolated Phase 7C backend disables generic Solana queries/spending and exposes only its selected swap projection. Session loss after restart needs explicit local history recovery; it never grants a new session the prior cross-chain history automatically.

`npm run phase7c:rehearsal` reads the real pinned route and simulates unsigned using the previously funded relayer; it does not create payment authorization or send. `npm run phase7c -- quote` creates the immutable local operator quote; `funding` and `funding-solana` query only the corresponding selected account. `prepare-payment` persists fixed native testnet bytes. Stop for exact human transaction-ID/amount/fee/expiry approval before `broadcast-payment <txid> --allow-testnet-broadcast`. `observe` waits for verified confirmation eligibility. `prepare-solana` persists reviewed swap bytes/digest. Stop again before `broadcast-solana <digest> --allow-devnet-broadcast --unlock-local-dpapi`. Use `reconcile` for the original signature only.

Funding is not settlement approval. The initial top-up workflow in `scripts/phase7c-funding.ts` is preserved for recovery; it is no longer needed for the selected direct-inventory checkout. `scripts/phase7c-use-funded.ts --use-funded-phase7b-wallets` was explicitly invoked once before the immutable quote, after fresh expiry reviews of both interrupted constructions, to bind the user's selected funded sources. It refuses a second selection or changes after quoting. The expired/unknown Solana top-up is also preserved; do not clear claims or repeat old approvals. After browser restart, pair/verify exactly one local session, then explicitly run `npm run phase7c -- attach-history --allow-local-history-recovery` to rotate old history handles and expose the existing order to that session without granting another payment or execution.
