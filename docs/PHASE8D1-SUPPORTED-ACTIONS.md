# Supported-action compatibility matrix

All rows have **execution disabled in Phase 8D.1**. “Existing adapter” means the historical settlement engine has a narrow implementation, not that arbitrary imported dApp requests can use it. EVM allowlist entries must be explicitly configured and code-hash pinned; no deployed addresses are guessed.

- **NFT mint / Base Sepolia** — recognizes the exact Phase 0 tuple/signature ABI at a configured target. Zero native value; fixed mint-price field; connected recipient. Existing adapter: yes. Preview: synthetic fixture verified. Missing for imported execution: signature, nonce/consumed state, live deployment configuration, payment and financial authorization. Ethereum/Robinhood tuple mint is rejected by registry.
- **NFT purchase / Base Sepolia, Ethereum Sepolia, Robinhood testnet** — recognizes `buy(id,recipient)` only at configured marketplace. Connected recipient; native price ≤0.001 test ETH (registry can tighten). Existing adapter: yes. Preview: synthetic Base fixture verified, shared testnet policy applies. Missing: listing ownership/expiry/price and executor quote/signature checks; network-specific deployment validation.
- **Native-input token swap / Base Sepolia** — recognizes `swapExactETHForTokens` at configured router with exactly pinned wrapped-native/output route. Input ≤0.0002 test ETH, positive minimum, bounded expiry. Existing adapter: yes, one route. Preview: synthetic verified. Missing: fresh reserve/quote/reference-block verification, expected output/slippage and recipient financial signature. Unknown routers and alternative paths are unsupported.
- **SOL delivery / Solana devnet** — canonical unsigned single system transfer of 0.001/0.002/0.005 SOL. Fee ≤0.00001 SOL; no rent. Existing adapter: yes. Local inspection: synthetic verified. Requires trusted genesis/blockhash/account checks and simulation; no dApp signing feature.
- **Raydium CPMM swap / Solana devnet** — exact 0.001 WSOL input, decimals 9→6, 1% slippage; pinned program `DRaycpLY18LhpbydsBWbVJtxpNv9oXPgjRSfpF2bWpYb`, pool `12aukygfT6qr5KH9MeeVYb4Y9rsmTzAVzUn633BRCfd`, output `2j76mnkJEBxbYv8T9c76PbsGzf5XuhpRoK1kwwTg9MpY`. Existing adapter: yes, one route. Local inspection: synthetic verified, five canonical instructions. Fee/rent/debit caps and program hash pinned. Live pool/account/quote evidence is a required trusted read dependency, not supplied by a dApp.
- **ERC20 transfer** — decode token target, recipient and raw amount; decimals remain unknown. Existing ZEC-funded imported-transfer adapter: no. Preview classification only, unsupported.
- **ERC20 approval** — decode spender and amount; finite and unlimited approvals remain unsupported. No adapter or execution permission; unlimited approval explicitly prohibited.
- **Unknown contract/method/router, arbitrary EVM call, mainnet, Solana extra instructions/programs/compute-budget changes/ALTs, generic SPL transfer** — unsupported or rejected. No execution fallback.

For supported shapes, simulation is required for a passed preview status, exact scoped preview consent is required, and separate settlement authorization is still absent. Historical completed-order replay guards are unchanged. Real third-party dApp transaction-level compatibility is **not verified** by these fixtures.
